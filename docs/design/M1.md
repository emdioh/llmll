# M1 — Curriculum, event log, projections, FSRS, flashcards

Design spec for milestone M1 (see `ARCHITECTURE.md` §13). Requirements references are `R§n`,
architecture references `A§n`. This document is the contract for implementation; deviations
must be recorded at the end of this file.

**Usable result:** the learner declares their level, then runs flashcard sessions whose
scheduling is driven by FSRS over an append-only event log.

## 1. Curriculum YAML schema

Location: `curriculum/de/`. Validated by Pydantic models in `backend/app/curriculum/schema.py`.

### 1.1 Lexicon — `curriculum/de/lexicon/{a1,a2,b1}.yaml`
A YAML list of entries:

| Field | Type | Rules |
|---|---|---|
| `id` | str | `^lex:[a-z0-9-]+(#[a-z0-9-]+)?$`, unique; `#sense` suffix for homonyms (`lex:bank#money`) |
| `lemma` | str | dictionary form, German spelling (`Tisch`, `gehen`, `schön`) |
| `pos` | enum | `noun verb adj adv prep conj pron det num particle phrase` |
| `gender` | `m` \| `f` \| `n` \| null | required for nouns unless `plural_only: true` |
| `plural` | str \| null | nouns only: full plural form (`Tische`); null if none |
| `plural_only` | bool | default false |
| `level` | `A1`…`C2` | |
| `translations` | `{it: str, en: str}` | both required; comma-separate alternatives (`tavolo, tavola`) |
| `example` | `{de: str, it: str}` | optional but strongly recommended |
| `verb` | object | verbs only, optional: `aux: haben\|sein`, `separable: bool`, `irregular: bool`, `praeteritum: str`, `partizip: str` |
| `prep_case` | `acc` \| `dat` \| `gen` \| `acc_dat` | prepositions only |
| `interference` | object | optional: `it_gender: m\|f` (Italian gender of the main translation, nouns), `false_friend: {lang: en\|it, word: str, note_it: str}`, `note_it: str` |
| `requires` | list[id] | optional prerequisites |

### 1.2 Grammar — `curriculum/de/grammar/<slug>.yaml`
One file per grammar point:

| Field | Type | Rules |
|---|---|---|
| `id` | str | `^gram:[a-z0-9-]+$`, file name = slug |
| `title_it`, `title_en` | str | |
| `level` | CEFR | |
| `requires` | list[id] | |
| `diagnostic_tags` | `{dimension: [values]}` | may be empty `{}` |
| `reference_it` | str (Markdown) | curated reference: rule, table if useful, examples, typical errors of Italian speakers |
| `examples` | list of `{de, it}` | at least 2 |

### 1.3 Constructions — `curriculum/de/constructions.yaml`
List of: `id` (`^cx:[a-z0-9-]+$`), `pattern` (`Lust haben auf + Akk`), `level`, `translations {it, en}`,
`example {de, it}`, `requires`.

### 1.4 Validation rules (importer)
- Schema validation per entry, errors reported as `file:index: message`, all errors at once.
- Unique ids across all files; every `requires` id exists; prerequisite graph is acyclic.
- Content is **original** (LLM-drafted, human-reviewed). Do not copy proprietary lists
  (Goethe, Profile Deutsch) into the repo (R§13).

## 2. Database (Alembic migration `0002`)

All timestamps are timezone-aware UTC. JSON columns use SQLAlchemy `JSON`.

- **`items`**: `id` str PK; `kind` (`lemma|grammar|construction`); `cefr_level`; `payload` JSON
  (the entry minus `id/kind/level/interference/requires`); `interference` JSON; `frequency_zipf`
  float null (lemmas, from `wordfreq.zipf_frequency(lemma, "de")`); `source_file`; `content_hash`;
  `suspended` bool.
- **`item_prerequisites`**: (`item_id`, `requires_item_id`) composite PK, both FK → items.
- **`learner_items`**: (`learner_id`, `item_id`) PK; `status`
  (`unseen|presumed_known|candidate|introduced|suspended`); `candidate_source`
  (`optin|article|wordlist`) null; `candidate_since`, `introduced_at` null.
- **`exercises`**: `id` PK; `learner_id`; `type` (`flashcard_intro|flashcard_recognition|flashcard_production`
  in M1); `prompt` JSON; `solution` JSON; `targets` JSON `[{item_id, facet, weight}]`;
  `generator` str (`flashcards.v1`); `created_at`; `session_id` str.
- **`attempts`**: `id` PK; `exercise_id` FK; `answer` JSON; `used_hint` bool; `duration_ms` int null;
  `outcome` (`correct|assisted|error`); `submitted_at`.
- **`learning_events`** (append-only — no UPDATE except setting `voided_by`): `id` PK autoincrement;
  `learner_id`; `item_id`; `facet` (`recognition|production`); `ts`; `kind`
  (`review|implicit|lookup|introduce|status_change`); `outcome` (`correct|assisted|error`) null;
  `evidence_weight` float; `diagnostic_tags` JSON list; `presumed_known` bool (item status was
  `presumed_known` when the event was recorded); `confidence` float default 1.0; `exercise_id`,
  `attempt_id`, `evaluation_id` null; `voided_by` int null. Index on
  (`learner_id`, `item_id`, `facet`, `ts`, `id`).
- **`item_memory`** (projection): (`learner_id`, `item_id`, `facet`) PK; `fsrs_card` JSON
  (`Card.to_dict()`); `due` (indexed); `stability`, `difficulty` float null; `mastery` float;
  `n_effective` float; `tag_error_counts` JSON; `last_event_id` int; `projection_version` str.
- `learners.settings` JSON gets the learner settings (§4.2).

Facets: lemmas have `recognition` and `production`; grammar and constructions use `production` only.

## 3. Domain (pure functions, `backend/app/domain/`)

No database, network or clock access: `now` is always a parameter.

### 3.1 `config.py`
Frozen dataclass `ProjectionConfig`:
- `desired_retention = 0.85`
- `alpha = 0.3`, `decay = 0.9` (mastery EWMA and `n_eff` decay)
- `evidence_weights`: `flashcard_recognition 0.5`, `flashcard_production 0.8`, `guided 1.0`,
  `translation 1.0`, `free 1.2`, `implicit_reading 0.2`, `implicit_sentence 0.6`, `lookup 0.5`
- `slip_mastery_threshold = 0.75`, `slip_min_n_eff = 3.0`
- `uncertain_confidence = 0.5`
- `version` property: short hash of all fields — stored as `projection_version`.

### 3.2 `mastery.py`
```
x = {correct: 1.0, assisted: 0.5, error: 0.0}[outcome]
m_new = m + alpha * w * (x - m)          (clamp alpha*w to ≤ 1)
n_new = decay * n + w
```
Initial `m = 0.5`, `n = 0.0`. Uncertain events (`confidence < uncertain_confidence`) use `w * confidence`.
`tag_error_counts`: on error, every tag `+1`; on any event every count `*= decay`; drop counts < 0.05.

### 3.3 `grading.py`
`grade(outcome, mastery, n_eff, confidence, presumed_known, is_first_review, cfg) -> GradeDecision`
with `rating: Rating | None` and `needs_remediation: bool`:
- `confidence < uncertain_confidence` → `rating=None` (no FSRS update).
- `correct` → `Good`; `Easy` if `presumed_known and is_first_review`.
- `assisted` → `Hard`.
- `error` → `Hard` if `mastery ≥ slip_mastery_threshold and n_eff ≥ slip_min_n_eff`
  (slip), else `Again` with `needs_remediation=True`.
Mastery and n_eff passed in are the values **before** this event.

### 3.4 `scheduling.py`
- One `fsrs.Scheduler(desired_retention=cfg.desired_retention, learning_steps=(), relearning_steps=(), enable_fuzzing=False)`.
  No learning steps: items are introduced inside exercises, not drilled within a session;
  no fuzzing: projections must be deterministic.
- Card ids are deterministic: `zlib.crc32(f"{item_id}|{facet}")`.
- `retrievability(card, now)`.

### 3.5 `projection.py`
- `MemoryState` frozen dataclass: `card` (fsrs Card | None), `mastery`, `n_eff`, `tag_error_counts`,
  `last_event_id`, `review_count`.
- `apply(state, event, cfg) -> (MemoryState, GradeDecision | None)`:
  - `introduce`: if no card, create card and review it with `Good` at `event.ts` (first exposure);
    mastery unchanged.
  - `review` / `implicit` / `lookup`: compute grade (§3.3); if `rating` is not None, review the card
    (creating it first if needed); update mastery/n_eff/tags.
  - `status_change`: no memory effect (only `last_event_id`).
- `replay(events, cfg)`: fold `apply` from the initial state over events sorted by (`ts`, `id`).
  Callers pass only non-voided events.
- **Invariant (tested):** applying events one by one equals `replay` of the same list.

### 3.6 `budget.py`
`new_item_budget(introduced_lemmas_7d, introduced_grammar_7d, backlog, settings) -> NewItemBudget(lemmas, grammar)`:
base = weekly limit − introduced in the last 7 days (≥ 0); if `backlog > 2 * review_cap` → 0;
elif `backlog > review_cap` → half (floor).

### 3.7 `selection.py`
`select_due(memories, now, limit)`: memories with `due ≤ now`, ordered by retrievability ascending,
then `frequency_zipf` descending (missing = 0), then item id. Pure; takes plain dataclasses.

### 3.8 `answers.py` — flashcard answer checking
- `check_recognition(choice_index, correct_index) -> correct|error`.
- `check_production(answer, expected_lemma, expected_gender|None) -> (outcome, diagnostic_tags)`:
  normalize (NFC, trim, collapse spaces, casefold for comparison; accept `ss` for `ß`); for nouns
  the answer must be `article + noun` (`der/die/das`); wrong article with right noun → `error`,
  tag `gender`; missing article → `error`, tag `article_missing`; `ae/oe/ue` written for umlauts or
  Levenshtein distance 1 on the noun/lemma → `assisted`, tag `spelling`; exact → `correct`.
  `used_hint` turns `correct` into `assisted` (done by the service).

## 4. Services and API

### 4.1 Learner and setup
- `GET /api/learner` → 404 if none, else `{id, level, known_languages, explanation_language, settings}`.
- `POST /api/learner` `{level, known_languages, explanation_language}` → creates learner 1 (409 if exists).
  Initial statuses (no events): items with level **below** the declared level → `presumed_known`;
  lemmas **at** the declared level → `candidate` (`candidate_source=wordlist`); everything else → `unseen`.
- `PUT /api/learner` `{level?}`: re-applies the rule only to items that have no events yet.

### 4.2 Settings
`GET/PUT /api/settings`: `{weekly_new_lemmas: 20, weekly_new_grammar: 2, desired_retention: 0.85, review_cap: 15}`.
`desired_retention` overrides `ProjectionConfig.desired_retention` (changes the projection version →
full replay on change).

### 4.3 Session
`POST /api/sessions` → builds a session and returns `{session_id, cards: [Card]}`:
1. Due memories via `select_due` (lemmas only in M1), up to `review_cap`. A due `recognition` facet
   becomes a recognition card, `production` a production card. At most one card per item per session
   (the lower-retrievability facet wins).
2. New lemmas within the budget (§3.6), taken from candidates ordered by `candidate_source`
   priority (`optin > article > wordlist`), then level, then `frequency_zipf` desc. In M1 each new
   lemma gets a `flashcard_intro` card (full info: article, plural, translations, example, interference
   note). M2 replaces this with exercise-based introduction (R§7.4).
3. Order: interleave intros among reviews (one intro every ~3 reviews).
Each card is an `exercises` row. Card payload:
`{exercise_id, type, item_id, prompt: {...}, hint?: str}` — never includes the solution, except intro cards.
- Recognition prompt: `{de: "der Tisch", options: [4 Italian translations]}`; distractors: same `pos`,
  same or adjacent level, deterministic per exercise (seeded by exercise id).
- Production prompt: `{it: "tavolo", pos: "noun", needs_article: true}`; hint = first letter + length.

`POST /api/sessions/{session_id}/answers` `{exercise_id, answer: {choice?: int, text?: str}, used_hint: bool, duration_ms?: int}`
→ records `attempt`; emits events; updates the projection incrementally; returns
`{outcome, expected: {...}, diagnostic_tags, feedback_it: str, memory: {facet, due, mastery}}`.
- Intro card answered (`answer: {}`) → `introduce` events for both facets, status `introduced`.
- Recognition → `review` event on `recognition` facet, weight `flashcard_recognition`.
- Production → `review` event on `production` facet, weight `flashcard_production`.
- First real event on a `presumed_known` item sets `presumed_known=true` on the event and moves the
  status to `introduced` (with a `status_change` event).
- `feedback_it` is template-based in M1 (e.g. gender error: «Attenzione: in tedesco è *der* Tisch
  (maschile).» plus the interference note if `it_gender` differs).

### 4.4 Corpus and grammar
- `GET /api/items?kind=&level=&status=&q=&limit=50&offset=0` → `{total, items: [{id, kind, level,
  label, translation_it, status, memory: [{facet, due, mastery, stability}]}]}`.
- `GET /api/items/{id}` → full item + learner status + memory.
- `GET /api/grammar` → list `{id, title_it, level}` by level; `GET /api/grammar/{id}` → full entry.

### 4.5 Maintenance
- `python -m app.cli import-curriculum [--path ../curriculum/de]`: upsert by id; changed content
  updates `payload/content_hash`; ids no longer present → `suspended=true` (never deleted);
  prerequisites rebuilt; creates `learner_items` rows for new items if a learner exists (status per §4.1).
- `python -m app.cli replay`: rebuild all `item_memory` rows from events; report count.
- `python -m app.cli export-openapi <path>`: write the OpenAPI JSON.
- On startup nothing is imported automatically. The Docker CMD runs `import-curriculum` after migrations.

## 5. Frontend
- **Onboarding:** if `GET /api/learner` is 404, show a setup form (level A1–C1, known languages,
  explanation language) before anything else.
- **Session view:** "Start session" → cards one at a time:
  - intro card: full info + "Got it";
  - recognition: German word + 4 option buttons;
  - production: Italian prompt + text input (autocapitalize off, autocorrect off, lang="de") +
    "Hint" + "Check"; offer buttons for `ä ö ü ß` above the input.
  - After answering: outcome, expected answer, `feedback_it`, then "Next". End: summary
    (reviewed, new, errors).
- **Corpus view:** filters (kind, level, status, search), list with status, mastery bar, next due.
  Item detail page.
- **Grammar view:** list grouped by level; detail renders `reference_it` Markdown (`react-markdown`).
- **Settings:** level, weekly limits, retention, review cap; backend health.
- API types are generated: backend `export-openapi` → `frontend/src/api/openapi.json` (committed) →
  `npm run gen:api` → `src/api/schema.d.ts` (committed). CI checks both are up to date.

## 6. Tests (must exist)
- Domain: mastery, grading table (every row of R§4.3), budget, selection order, answer checking
  (gender error, missing article, umlaut alternative, typo, ß/ss).
- Projection invariant: random event sequences (seeded) — incremental == replay; replay twice ==
  identical; changing `desired_retention` changes `version`.
- Importer: valid fixture imports; duplicate id, missing prerequisite, cycle, schema error each
  rejected with file:index; re-import is idempotent; removed id → suspended.
- Real curriculum: `curriculum/de` validates (test runs the validator on the real files).
- API: setup → session → answers flow end to end with the real domain (no mocks); presumed-known
  first review; replay after the flow equals incremental state.

## 7. Seed content (M1)
Original content, drafted and reviewed:
- Lexicon: ~200 A1, ~200 A2, ~150 B1 high-frequency lemmas, balanced across parts of speech,
  with examples. Interference fields filled for nouns where the Italian gender differs.
- Grammar: ~20 points A1–B1, including the word-order stages (R§5), cases and articles,
  prepositions (acc/dat/two-way), adjective endings, Perfekt with haben/sein, separable verbs,
  modal verbs, subordinate clauses (`weil`, `dass`, `wenn`), Präteritum of sein/haben/modals,
  comparative/superlative, reflexive verbs, relative clauses, Konjunktiv II (`würde`, `hätte/wäre`),
  passive (B1).
- Constructions: ~30 common ones.

## Deviations
_(record any deviation from this spec here, with the reason)_

Backend implementation:

- **`learners` columns.** The spec lists learner fields (`level`, `known_languages`,
  `explanation_language`) but no columns; migration `0002` adds them to `learners` (with server
  defaults) instead of hiding them in `settings`.
- **`MemoryState.review_count` dropped.** `item_memory` has no column for it, so incremental
  state and replay could not agree. `is_first_review` is "no FSRS card yet", which is equivalent
  for the presumed-known `Easy` rule (a card exists after the first rated review or introduce;
  uncertain events do not create one). `MemoryState` carries `card_id` instead.
- **`item_memory.fsrs_card` and `due` are nullable.** An uncertain first event updates mastery
  without creating a card.
- **`content_hash` is per entry** (sha256 of the canonical entry JSON), not per file, so a change
  only touches the items that changed.
- **Error positions.** Grammar files hold a single entry and are reported as `file:0: message`;
  the cycle error has no single position and reads `prerequisite cycle: a -> b -> a`.
- **YAML booleans in `diagnostic_tags`.** Bare `true`/`false` values are coerced to the strings
  `"true"`/`"false"` (YAML would otherwise turn them into booleans); quoting is still preferred.
- **Typo tolerance.** Levenshtein distance 1 only applies to words of 4+ characters; otherwise
  short words (`an`/`ab`) would count as "assisted spelling" instead of errors. A wrong article
  plus a misspelled noun reports tags `["gender", "spelling"]`.
- **`check_production` gender argument.** Plural-only nouns pass `expected_gender="pl"`
  (article `die`); non-nouns pass `None`.
- **Facet tie-break.** When two facets of the same item are equally retrievable (e.g. just
  introduced), recognition is shown first; the other facet reappears in a later session.
- **Backlog** for the new-item budget is the number of distinct due lemmas (before the
  `review_cap`), not the number of due facet rows.
- **`select_due`** takes an extra `desired_retention` argument (default 0.85) to compute
  retrievability with the learner's scheduler.
- **Settings update.** `PUT /api/settings` merges the given fields (all optional) rather than
  requiring the full object; a change of `desired_retention` triggers a full replay of the
  learner's events synchronously.
- **HTTP status codes.** `POST /api/learner` and `POST /api/sessions` return 201; answering an
  exercise twice returns 409; endpoints needing a learner return 404 before setup.
- **Intro cards** record `introduce` events with `evidence_weight` 0 and no `status_change`
  event; `learner_items.status` moves to `introduced` directly. The card `prompt` is one Pydantic
  model with optional fields (`CardPrompt`) covering all card types, null when unused.
- **Item ids with `#`** (`lex:bank#money`) must be URL-encoded (`%23`) by clients in
  `GET /api/items/{id}`.
- **Importer on re-appearing ids.** A suspended id that reappears is un-suspended.
  `learner_items` rows are not touched when an item is suspended; selection and the grammar list
  ignore suspended items, `GET /api/items` still lists them.
- **Datetime handling.** All datetime columns use a `UTCDateTime` type decorator, so values read
  from SQLite are always timezone-aware UTC.
- **`new_per_session` setting (coordinator request).** New learner setting `new_per_session`
  (default 5, validated 0-20), exposed in `GET/PUT /api/settings`. A session offers at most
  `min(weekly budget, new_per_session)` new lemmas, so the weekly budget is no longer spent in one
  session (R§10).
