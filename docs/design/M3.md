# M3 — Reading: ingestion, simplification with coverage, glossary, candidates

Design spec for milestone M3 (see `ARCHITECTURE.md` §13). Builds on M1/M2.
References: `R§n` requirements, `A§n` architecture. Deviations go at the end of this file.

**Usable result:** the learner pastes a link or a text, gets a version simplified to their level
with measured lexical coverage, reads it with tap-to-gloss, writes a short summary that is graded,
and the words met feed the candidate queue and implicit reviews.

## 1. NLP layer (`backend/app/nlp/`, A§8)

### 1.1 Analyzer (`analyzer.py`)
- spaCy German pipeline, model `de_core_news_md` (installed as a pinned wheel dependency in
  `pyproject.toml` so `uv sync` and the Docker build get it; loaded once, lazily, cached on
  `app.state`). Only the components needed: tokenizer, tagger/morphologizer, lemmatizer, NER.
- `analyze(text) -> list[Token]`: `Token{i, text, start, end, lemma, pos, is_alpha, is_punct, is_propn,
  ent_type}`.
- Lemma normalization for lookup: the lexicon key is the lemma as written in the curriculum
  (`Tisch`, `gehen`); match on exact lemma first, then case-insensitive. Separable verbs: spaCy splits
  the particle (`ruft ... an`); in M3 accept the base-verb match and record the miss in metrics (no
  particle reattachment).
- A `FakeAnalyzer` (regex tokenizer, identity lemma) for tests that don't need spaCy; one test module
  uses the real model and is marked `@pytest.mark.spacy` (run in CI).

### 1.2 Compounds (`compounds.py`)
`split_compound(word, known_lemmas) -> list[str] | None`: dynamic-programming split of a noun into
known lexicon lemmas (case-insensitive), allowing the linking elements `s`, `es`, `n`, `en`, `e`
between parts; minimum part length 3; the head (last part) must be a noun lemma. Returns the parts if
every part is known, else `None`. No external library (a self-contained, tested function is simpler to
maintain than CharSplit for this narrow use; revisit if recall is poor).

### 1.3 Frequencies
`wordfreq.zipf_frequency(lemma, "de")` (already used in M1).

### 1.4 Text extraction (`extract.py`)
`fetch_article(url) -> ExtractedText{title, text, url}` with `httpx` (timeout 10 s, browser-like UA,
max 2 MB) + `trafilatura.extract`. Failure (HTTP error, paywall, empty extraction) raises
`ExtractionFailed(reason)` → API returns 422 with `reason`, and the UI asks to paste the text.
Language check: if the extracted text is not German (simple heuristic: share of tokens that are
German stopwords < 10%), it is flagged `source_language = "other"` and treated as a translation source.

## 2. Word classification (pure: `app/domain/words.py`, R§7.3, A§5.5)
`classify(token_lemma, pos, is_propn, learner_view, current_level) -> WordClass` where `learner_view`
gives, per lexicon lemma, its item id, CEFR level and learner status:
- proper noun / NER person-place-org / number / punctuation → `ignore`;
- lemma in the lexicon with status `introduced` → `known`; `presumed_known` → `presumed_known`;
- lemma in the lexicon, status `candidate`/`unseen`, level ≤ current → `auto_candidate`;
- lemma in the lexicon, level > current → `optin`;
- not in the lexicon: compound fully split into known parts → `ignore_compound` (with parts);
  otherwise `optin_unlisted` (no item exists; opt-in creates a learner-specific item, §5).

Coverage (pure): `coverage(tokens, classes) = (#alpha non-ignored tokens that are known|presumed_known|ignore_compound) / (#alpha non-ignored tokens)`.

## 3. Simplification (`simplify_text` LLM task)
- Request: source text (German, or Italian/English for translation), target level, explanation
  language, **allowed vocabulary** (lemmas `introduced`/`presumed_known`, plus up to 10 `auto_candidate`
  lemmas found in the source, chosen by frequency), style notes (short sentences, main-clause first,
  only grammar points the learner has met — list them), target length (≤ 120% of source for short
  texts; summarize long texts to ≤ 400 words).
- Response (`SimplifiedText`): `title`, `paragraphs: [str]`, `new_words: [{lemma, translation}]`,
  `notes` (what was cut or summarized).
- Loop (service): analyze → classify → coverage; if coverage < `cfg.coverage_target` (0.95), retry with
  the list of out-of-vocabulary lemmas to replace, at most `cfg.max_simplify_attempts` (3); keep the best
  attempt; store all attempts.
- Model task config: `simplify_text` → `claude-opus-5-5`, effort `medium`, max_tokens 8000.

## 4. Data model (migration `0004`)
- `texts`: `id`, `learner_id`, `source_url` null, `source_title`, `source_text`, `source_language`,
  `created_at`.
- `text_versions`: `id`, `text_id`, `level`, `title`, `body` (paragraphs joined with blank lines),
  `coverage` float, `attempt` int, `llm_call_id`, `selected` bool, `analysis` JSON (tokens with
  `start, end, lemma, item_id, class`), `created_at`.
- `reading_sessions`: `id`, `text_version_id`, `started_at`, `finished_at` null, `lookups` JSON
  (item ids / lemmas tapped).
- `glosses`: cache `(lemma, context_hash) → {translation, lemma, gender, plural, note}`.

## 5. Reading flow and effects
- `POST /api/texts {url? , text?}` → creates the text, runs simplification synchronously (may take
  10–30 s; the UI shows progress) → returns the selected version with token analysis.
  Long-running: implemented as a normal request with a generous timeout; no job queue in v1.
- `GET /api/texts`, `GET /api/texts/{id}` (selected version + original).
- `POST /api/texts/{id}/reading` → starts a reading session.
- **Tap-to-gloss** `POST /api/reading/{rid}/gloss {token_index}` → gloss: lexicon data when the lemma
  is in the curriculum (no LLM), otherwise `gloss` LLM task (cached; model task config `gloss` →
  `claude-opus-5-5`, effort `low`, max_tokens 500). Emits a `lookup` event (weight `lookup`, outcome
  `assisted`) when the lemma is a known/presumed item.
- **Opt-in** `POST /api/reading/{rid}/optin {token_index}`: lexicon lemma → status `candidate`,
  `candidate_source=optin`. Unlisted lemma → creates a learner-specific item `lex:user-<slug>` from the
  gloss (kind `lemma`, `payload.user_created = true`, level = learner level) and makes it a candidate.
  User-created items are stored in `items` with `source_file = "user"` and are never suspended by
  the importer.
- **Finish** `POST /api/reading/{rid}/finish` →
  - `implicit` events (outcome `correct`, weight `implicit_reading`) for each distinct `known` /
    `presumed_known` item in the text that was not looked up, capped at `cfg.max_implicit_per_text`
    (30, highest-frequency first);
  - each distinct `auto_candidate` lemma → status `candidate`, `candidate_source=article`
    (if currently `unseen` or `candidate` from `wordlist`);
  - returns a `reading_summary` production exercise (prepared like M2 exercises; prompt: summarize or
    comment on the text in 2–4 German sentences; targets: up to 3 items from the text that are due or
    weak; graded with `grade_sentence`, evidence weight `free`).
- Texts generated from scratch (R§7.3 last bullet): `POST /api/texts/generate {topic?}` → the
  `simplify_text` task in generation mode, seeded with up to 15 due lemmas; same flow afterwards.

## 6. Frontend
- Reading view: list of texts; "New text" with URL or paste (tabs); progress state while simplifying;
  reader with the simplified text, tokens tappable, colour hints off by default (option to underline
  new words); gloss bottom sheet with translation, lemma, gender, plural, note, and "Aggiungi alle
  parole da imparare" for opt-in classes; "Show original" toggle; coverage shown discreetly; "Finish"
  → summary exercise (reuse the M2 production card + feedback components).
- Session view: link "Read something" to start a reading session (R§10 two session types).

## 7. Tests (must exist)
- `classify` and `coverage` rules; `split_compound` (Klimaschutzgesetz-style with linking `s`,
  negative cases).
- Extraction with `httpx.MockTransport` + a saved HTML fixture; failure → 422.
- Simplification loop with the fake LLM: retries until coverage target or max attempts; best kept.
- Reading finish effects: implicit events capped and weighted, candidates with source `article`,
  lookups excluded from implicit, opt-in of a listed and of an unlisted lemma.
- One real-spaCy test (marked) checking lemmas for a short German sentence.
- API end to end with fake LLM: create text → read → gloss → finish → summary exercise → answer.
